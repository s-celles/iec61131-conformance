## Search results

- `calls`, seeds 161–220, excluding the previously known formal-call,
  literal, CASE, MUX, NOT and inverted-LIMIT problems: IronPLC passes all
  60; STruC++ passes 51, with 9 C++ build errors. All nine involve
  extensible MIN/MAX mixing expressions and variable wrappers. Seed 166
  reduces to `ops/minmax_ext_expr`.
- The initial STRING exploration, before extending CONCAT generation,
  exercised seeds 101–180: 79 programs generated, one rejected because
  the evaluator could not find a defined execution. matiec passes 73;
  STruC++ passes 7. These are exploratory divergences, including known
  inverted-LIMIT and REPLACE issues and constructs in unexecuted branches;
  they are not a count of distinct compiler defects. Source inspection
  and separate variable-only probes exposed INSERT, FIND signedness,
  STRING selection and extensible CONCAT.
- After adding exclusions for the newly isolated problems, `calls`
  seeds 221–300 pass all 80 programs on IronPLC and STruC++.
- After extending CONCAT generation, default `strings` seeds 1–40 on
  IronPLC generate 38 defined programs (two discarded): 20 pass and 18
  fail with CONCAT's P4018 arity rejection. This confirms that the updated
  generator reaches the reduced extensibility defect without a manual
  probe. Reproduce with `--profile strings --seeds 1-40`, the IronPLC
  options below and a separate `--out` directory, without exclusions.
- With the STRING exclusions below, seeds 181–260 pass all 80 programs
  on IronPLC, matiec and STruC++. No seeds were discarded in either of
  these final campaigns. This only covers the generated executions and
  remaining constructs; excluded defects still have conformance tests.

## Reproduce the final campaigns

From the suite root, with the pinned checkouts built in sibling `scratch/`
and the harnesses built as in README:

```sh
scratch_dir=$(realpath ../scratch)
python3 -I tools/fuzz/run.py --profile calls --seeds 221-300 \
  --exclude std_formal,literal_args,case_call,mux_expr,not_expr,limit_inverted,ext_minmax \
  --out /tmp/st-calls-clean \
  --ironplc-harness harness/ironplc/target/release/iec61131-conformance-ironplc \
  --ironplcc ironplc-src/compiler/target/release/ironplcc \
  --strucpp "node $scratch_dir/strucpp/dist/node/cli.js" \
  --runtime-include "$scratch_dir/strucpp/src/runtime/include"

python3 -I tools/fuzz/run.py --profile strings --seeds 181-260 \
  --exclude literal_args,case_call,mux_expr,not_expr,limit_inverted,ext_minmax,string_order,string_int,string_insert,string_replace,ext_concat \
  --out /tmp/st-strings-clean \
  --ironplc-harness harness/ironplc/target/release/iec61131-conformance-ironplc \
  --ironplcc ironplc-src/compiler/target/release/ironplcc \
  --iec2c "$scratch_dir/matiec/iec2c" --matiec-lib "$scratch_dir/matiec/lib" \
  --strucpp "node $scratch_dir/strucpp/dist/node/cli.js" \
  --runtime-include "$scratch_dir/strucpp/src/runtime/include"

python3 -I tools/fuzz/test_gen.py
python3 -I harness/matiec/test_diagnostics.py
python3 -I formal/gen_traces.py
(cd formal && lake build)
```

Compiler paths must be absolute: the Python harnesses invoke compilers
from temporary build directories. Initial relative-path invocations failed
before compiling any ST; those infrastructure errors are excluded from
the campaign totals above. Generated fuzz programs/traces stay outside
`conformance/` and are not committed.

## Evidence and limits

The complete 99-test suite was run on pinned IronPLC, matiec, OpenPLC's
matiec, STruC++, rk and 4diac. Observed outputs are in `notes/evidence/`;
the comparison table is regenerated by `python3 -I harness/summarize.py`.
RuSTy is absent locally, so its five additional cases have no evidence;
they remain ERROR (not run) until a RuSTy run supplies actual output.
The string/operation tests are outside the FB/scheduler Lean model;
`lake build` checks the existing model and trace proofs, not these new
string derivations.

Long C/C++ diagnostics exposed a harness issue: truncating stderr before
masking an absolute library path makes the final excerpt depend on the
checkout path length. Both Python C/C++ harnesses now mask the relevant
library root before taking 3000 characters. Build-error cases were rerun
after this change. It changes diagnostic text, not verdicts or ST semantics.
The regression test compares otherwise identical diagnostics from short
and long checkout paths.
