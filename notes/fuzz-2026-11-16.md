# Structure search, 2026-11-16

## Profiles

- `structs`: a type `PT : STRUCT x : INT; y : INT := 5; ok : BOOL;
  END_STRUCT`, variables `p0` and `p1 := (x := 2, ok := TRUE)`, an array
  `pa : ARRAY[0..2] OF PT` and an INT array `a1`. Members are read in
  expressions and written by assignments, and whole structures are copied
  between variables and elements. The reference evaluator copies the value
  on each assignment (ed.3 7.3.2.1).
- `struct_calls`: `structs` plus the user POUs of `calls`, with INT members
  also as F_TICK's VAR_IN_OUT and F_DM's VAR_OUTPUT.

## Results (IronPLC, matiec, OpenPLC fork, STruC++, rk)

Converix NixOS VM (`shell.nix`), base exclusions
`literal_args,case_call,mux_expr,not_expr,limit_inverted,ext_minmax`, plus
`std_formal,array_elem_args` for `struct_calls`. `structs` used 10
statements, seeds 1-500 (499 defined programs); `struct_calls` used 8
statements, seeds 1-500 (500 defined).

- STruC++ and rk pass all 999 programs.
- The OpenPLC fork rejects all 999: a non-integer literal in a structure
  initialiser (`ok := TRUE`), reduced to `data/struct_init` (fork item 14).
- IronPLC fails 665. 650 are a whole structure assigned to or from an
  array element (`pa[i] := p0`, `p0 := pa[i]`, open issue ironplc#1471,
  reduced to `data/struct_element_copy`, finding 30). 15 are a member as
  F_TICK's VAR_IN_OUT (`F_TICK(p0.x, ...)`, reduced to
  `pou/inout_struct_field`, an extension of finding 29 / ironplc#2615).
- matiec fails 40 `struct_calls` programs and no `structs` program. 23 have
  a member of an array element as an argument (`table__ULINT_LITERAL`,
  `tabledata__`, item 18 / beremiz/matiec#53, reduced to
  `pou/inout_struct_field` and `pou/output_struct_field`). The other 17 have
  a VAR_IN_OUT call inside another call's argument (item 17).

`array_elem_args` excluded elements of `a1` as arguments, but not members of
`pa`'s elements. It now excludes those too. `struct_elem_copy` and
`struct_field_inout` leave out the two IronPLC cases, and `struct_init` the
fork's.

The first launch of the 2026-11-16 array round was lost to a host OOM on
M75Q: a remote Nix build used the host while the VM held 12 of its 15 GiB.
The campaigns now run `run.py` under `python3 -u`, so a log keeps what was found
before an interruption.

## Second round, 2026-11-16

Past the round 1 defects, with
`struct_init,struct_elem_copy` and the base exclusions, plus
`struct_field_inout,std_formal,array_elem_args` for `struct_calls`:

- `structs`, seeds 501-1100, 10 statements: all 600 pass on IronPLC,
  matiec, the OpenPLC fork, STruC++ and rk.
- `struct_calls`, seeds 501-1100, 8 statements: IronPLC, STruC++ and rk pass
  all 600. matiec and the OpenPLC fork fail the same 37 (504 523 529 551 552
  555 595 620 630 634 647 680 684 692 706 722 729 760 780 802 805 822 861
  879 893 926 942 955 972 975 1002 1016 1030 1031 1051 1068 1084), all at
  link time ("undefined reference to `__MAIN_F_TICK<n>`/`F_DM<n>`", 41
  references):
  - 35 have the F_TICK/F_DM call inside another call's argument (item 17):
    MIN, MAX, ABS, SEL, LIMIT, or the user function `F_LIN(b := F_TICK(..))`,
    sometimes through parentheses (`ABS((F_TICK(..) MOD 6))`).
  - 529 and 1084 have F_TICK only as a `MOD` divisor
    (`a1[4] MOD F_TICK(v1, 8)`): the divisor is generated twice (item 16).
  - In 555, 620, 630, 634, 706, 780 and 1030 the call after the nested one
    is undefined too. Stage 4 numbers every call, but the wrapper generator
    numbers only the calls it visits, so it emits the later call's wrapper
    under the skipped number. In 634, `MAX(.., F_DM(..))` and then
    `v1 := F_TICK(..)` reference `__MAIN_F_DM1` and `__MAIN_F_TICK2`, and
    only `__MAIN_F_TICK1` is defined. In 555, two F_TICK calls reference
    `__MAIN_F_TICK1` and `__MAIN_F_TICK2`, and the one wrapper,
    `__MAIN_F_TICK1`, is the later call's.

  matiec `c316fe5` gives the same undefined references on all 37 (same
  programs, regenerated with the same options). None involves a structure.
  No new defect.

## Reproduce

```sh
X=literal_args,case_call,mux_expr,not_expr,limit_inverted,ext_minmax
python3 -u -I tools/fuzz/run.py --profile structs --seeds 1-500 --stmts 10 \
  --exclude $X --out /tmp/st-structs <runtime options as in notes/fuzz-2026-11-15.md>
python3 -u -I tools/fuzz/run.py --profile struct_calls --seeds 1-500 --stmts 8 \
  --exclude std_formal,array_elem_args,$X --out /tmp/st-struct-calls <...>
```
